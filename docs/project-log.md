# Project Log

Running record of the work, decisions and status of the `lapse-prediction` project. Entries are added at the end of each working session, newest last.

## Project summary

An end-to-end system to predict lapse (non-payment and termination) of protection insurance policies. All data is synthetic and generated by code in this repository. No proprietary, confidential or real customer data is used, and synthetic distributions are not calibrated to any real insurer.

**Phase 1 scope (to 31 Jan 2027):** structured Python repository, automated tests, consistent Git workflow, reproducible training and evaluation, and documented modelling decisions, metrics and limitations.

## Decision record

| Date | Decision | Rationale |
|---|---|---|
| 02 Nov 2026 | Use synthetic insurance-lapse data rather than a public churn dataset | Matches the insurance domain; allows realistic time structure and time-based validation; allows controlled drift for later monitoring work. Trade-off: less realistic noise, and metrics are not evidence of real-world performance |
| 02 Nov 2026 | Tooling limited to uv, ruff, pytest and pre-commit | Minimal set covering environment management, linting, formatting and testing. Experiment tracking, CI, APIs and containers deferred to later phases |
| 05 Nov 2026 | `src/` package layout | Separates importable code from tests and scripts; avoids accidental imports from the working directory |
| 05 Nov 2026 | Anchor `/data/` and `/artifacts/` in `.gitignore` | The unanchored pattern `data/` excluded the source package `src/lapse/data/` |
| 23 Nov 2026 | Feature-branch workflow with pull requests into `main` | `main` stays in a working state; each change is reviewed before merging |
| 23 Nov 2026 | Generator v1 limited to five static policy fields | Establishes the generator and testing pattern before adding modelling complexity |
| 23 Nov 2026 | Behavioural signals (missed payments, contacts, amendments) to be stored in a dated events table, not as fields on the policy table | Counts such as "missed payments in the last year" depend on a reference date. Storing raw dated events allows features to be computed strictly before the prediction date, so leakage can be prevented and tested. Missed payments are closely linked to lapse itself and are the main leakage risk |
| 23 Nov 2026 | Code written with AI assistance; all code reviewed, run and explained before merging | Focus on system design, verification and the ability to explain and defend every line |
| 25 Nov 2026 | Premium derived from cover, age and product rather than drawn at random | Produces realistic relationships for the lapse model to learn; resolves the v1 limitation |
| 25 Nov 2026 | Behaviour tests assert a minimum margin, not only a direction | A direction-only assertion can pass by chance when the effect is absent; confirmed by sabotage check |
| 25 Nov 2026 | Lapse generated as a monthly risk from policy start to an observation end date of 31 Dec 2025; policies still in force are censored (no `lapse_date`) | Mirrors a real data extract; makes duration effects possible; censoring must be handled in problem framing |
| 25 Nov 2026 | Lapse drivers (multipliers on monthly risk): duration baseline about 12% / 9% / 6% annual for years 1 / 2 / 3+; monthly payment 1.5x; card 1.4x; mortgage protection 0.7x, income protection 1.2x; about 1.2x per doubling of premium; random broker effects (about 0.75x–1.35x); region and age no direct effect | Invented, round assumptions based on general reasoning; each will be a named constant and covered by a behaviour test |
| 25 Nov 2026 | Hidden per-policy financial-pressure score drives both lapse and missed payments; stored as an internal column and excluded from model features, enforced by a test | Makes missed payments predictive of lapse without encoding the outcome directly |
| 25 Nov 2026 | Events table to hold four event types: `missed_payment`, `contact`, `amendment`, `indexation`. `amendment` is cut first if the work overruns | Indexation is a recognised lapse trigger; days since an event is computed at snapshot time, not stored as a field |
| 25 Nov 2026 | New business written continuously from 2018 to the observation end date (31 Dec 2025) | Recent snapshots include first-year policies, the highest-risk period; increases censoring, which problem framing must handle. No policy reaches term expiry before 2028 (documented simplification) |
| 25 Nov 2026 | No behaviour test for broker effects | With 20 brokers and modest effects, sampling noise per broker is comparable to the effect, so the test would fail at random |

### 23 Nov 2026: Policy generator v1

- Resumed after a three-week pause; schedule revised (see above).
- Created branch `feat/policy-generator`.
- Added `src/lapse/data/generate.py` with `generate_policies(n_policies, seed)`:
  - `policy_id`: sequential IDs (`P000001` …)
  - `age_at_start`: uniform integers, 18–65 inclusive
  - `product_type`: term life 50%, income protection 20%, mortgage protection 30%
  - `annual_premium`: lognormal, centred near €600, rounded to 2 decimal places
  - `start_date`: uniform over approximately 2018–2023
  - Raises `ValueError` when `n_policies < 1`
  - Uses a local `numpy` random generator for reproducibility
- Added the first test: correct row count.
- Pre-commit reformatted two files (line joining, final newline); changes reviewed with `git diff` before committing.
- Noted pandas 3 behaviour: text columns use the `str` dtype, and datetimes use microsecond resolution (`datetime64[us]`).
- Added tests: determinism (same seed gives identical output; different seed gives different output), value ranges (unique IDs, age bounds, positive premiums, allowed product types) and input validation (`n_policies < 1` raises `ValueError`). 5 tests passing.
- Verified the determinism test by removing the seed: the same-seed test failed as expected; the different-seed test passed, showing that each test covers a different failure mode.
- Ruff flagged a duplicated test function (F811). Python silently overrides duplicate definitions, so a test would otherwise have been lost without warning.
- Opened PR #1 (`feat/policy-generator` into `main`).

**Known limitations (v1):** premium is independent of age and product; no policy term, sum assured, payment details or outcome yet.

**Planned for v2:** `term_years`, `sum_assured`, `premium_frequency`, `payment_method`, `broker_code`, `lapse_date`, one or two features with no signal, and an events table (`missed_payment`, `amendment`, `contact`).

### 25 Nov 2026: Generator v2, part 1 (policy fields and pricing)

- Split generator v2 into three pull requests: policy fields and pricing (#2), lapse outcome (#3), events table (#4).
- Added fields: `term_years`, `sum_assured`, `premium_frequency`, `payment_method`, `broker_code`, `region`.
- Replaced the random premium with a pricing formula: cover x base rate x age factor (about 6% per year of age) x product factor (income protection 2.5, term life 1.0, mortgage protection 0.8) x lognormal noise.
- `region` deliberately carries no signal and serves as a control feature. `broker_code` has no effect until the lapse mechanism is added.
- Added tests: explicit schema (column names and order), extended value ranges, and behaviour tests for age-based and product-based pricing. Introduced a shared pytest fixture. 8 tests passing.
- Sabotage check (age effect set to zero) showed the original age test passed by chance: the two medians differed by 0.00003. Added margins (older at least 2x younger; product ratios of 1.5x and 1.1x), set well below the designed effects. The test then failed as expected under sabotage.

### 25 Nov 2026: Lapse mechanism design

- Agreed the design for the lapse outcome (PR #3) and the event types for the events table (PR #4); see the decision record.

### 25 Nov 2026: Generator v2, part 2 (lapse outcome)

- Added a monthly lapse simulation from policy start to 31 Dec 2025: baseline by policy year multiplied by driver effects (frequency, payment method, product, premium, broker, hidden pressure). Policies in force at the end date are censored (`lapse_date` empty).
- Added `_latent_pressure` (internal) and `drop_internal_columns`, which removes all columns prefixed with `_` before modelling.
- Extended new business to the end of 2025.
- Added tests: lapse dates within the observation window, plausible overall lapse rate, first-year lapse at least 1.5x year-3 lapse, and behaviour tests for frequency, payment method, product and premium (within term life), a control test showing region has no material effect, and the internal-column guard. 17 tests passing.
- Sabotage check: removing the monthly-payment effect failed `test_monthly_payers_lapse_more` as expected.
